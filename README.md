# Storys Web

Bilingual (繁中 / EN) podcast website for **Storys Podcast** (formerly 創業之聲).

- **Stack:** [Astro](https://astro.build) static site generator, vanilla CSS, Leaflet for the map. No React. No CMS.
- **Hosting:** Netlify (with Netlify Forms for contact/sponsor/application).
- **DNS:** Cloudflare Registrar (recommended) → Netlify.
- **Episodes:** Synced daily from the podcast RSS feed via GitHub Action.

---

## Quick start

```bash
npm install
npm run dev          # local dev at http://localhost:4321
npm run build        # produces dist/
npm run preview      # serves the built site
npm run sync-episodes # refresh src/data/episodes.json from RSS
```

Requires **Node 22+** and **npm 10+**.

## Editing content

### Add or update a brand

Edit [`src/data/brands.ts`](src/data/brands.ts). Required fields per brand:

```ts
{
  id: "kkday",                 // unique slug
  nameZh: "KKday 酷遊天",
  nameEn: "KKday",
  category: "travel",          // see Category type
  type: "online",              // "retail" puts it on the map; "online" goes to the directory
  descZh: "亞洲領先的旅遊體驗預訂平台...",
  descEn: "Asia's leading travel-experiences marketplace...",
  domain: "kkday.com",         // drives logo via Google favicon API
  website: "https://www.kkday.com",
  episodes: [
    { num: 7, titleZh: "酷遊天 KKday｜創辦人 陳明明", appleId: "1000689073825" }
  ],
  // retail only — pin appears on the map for each location:
  locations: [
    {
      nameZh: "KKday 總部", nameEn: "KKday HQ",
      addressZh: "台北市信義區...", addressEn: "Xinyi District, Taipei...",
      lat: 25.038813, lng: 121.566800
    }
  ]
}
```

To find an episode's `appleId`: open the episode on Apple Podcasts, copy the URL,
take the number after `?i=`.

To geocode a new address — fastest way is [ArcGIS World Geocoding](https://geocode.arcgis.com/arcgis/rest/services/World/GeocodeServer/findAddressCandidates) (no key required):

```bash
curl -s "https://geocode.arcgis.com/arcgis/rest/services/World/GeocodeServer/findAddressCandidates?f=json&maxLocations=1&singleLine=台北市信義區松高路12號" | python3 -m json.tool
# location.x → lng, location.y → lat
```

### Add a translation

Edit [`src/data/i18n.ts`](src/data/i18n.ts). Add the key to **both** the `zh` and `en` blocks. Reference in any `.astro` file with `data-i18n="my.key"`.

### Add an episode manually

Append to the relevant brand's `episodes` array in `brands.ts`. The RSS sync will keep `episodes.json` fresh independently — but `brands.ts` remains the place to attach episodes to specific brands.

## Deploying to Netlify

1. **Push to GitHub.** Create a new repo `storys-web` (in your org or under your account), push this code.
2. **Sign in to [Netlify](https://app.netlify.com) with GitHub** → "Add new site" → "Import an existing project" → pick the repo.
3. Netlify auto-detects Astro. Confirm settings:
   - Build command: `npm run build`
   - Publish directory: `dist`
   - Node version: `22`
4. **Deploy.** First build takes ~2 minutes.

### Custom domain

1. In Netlify: **Site settings → Domain management → Add custom domain** → enter `storys.fm` (or whatever you bought).
2. Netlify will show you the DNS records to set at your registrar.
3. **Recommended setup:** Buy the domain at Cloudflare Registrar (at-cost pricing). Set Cloudflare nameservers as your registrar default. In Cloudflare DNS, add a `CNAME` record `@` → `your-site.netlify.app` (or `A` to Netlify's IP for apex domains). Propagation: ~5–30 minutes.
4. Netlify provisions HTTPS via Let's Encrypt automatically.

### Form notifications

In Netlify dashboard → **Forms** → you'll see three form names after first deploy:

- `contact` — general inquiries
- `sponsor` — sponsorship inquiries
- `brand-application` — guest applications

For each, click into it → **Notifications** → **Add notification** → "Email notification" → set the recipient inbox. Recommended:

- `contact` → `hi@storys.fm`
- `sponsor` → `sponsors@storys.fm`
- `brand-application` → `apply@storys.fm`

If you don't have those mailboxes yet, route everything to one inbox (e.g. your personal email) and add subject prefixes via Netlify's notification config.

## RSS episode sync

The site reads episodes from `src/data/episodes.json`. That file is regenerated by [scripts/sync-episodes.mjs](scripts/sync-episodes.mjs), which:

1. Tries `iTunes Lookup API` first (returns Apple `trackId` per episode — preferred).
2. Falls back to the show's anchor.fm RSS feed if iTunes Lookup fails.
3. Writes the result, sorted newest-first.

**Run locally:** `npm run sync-episodes`.

**Run on CI:** [.github/workflows/sync-episodes.yml](.github/workflows/sync-episodes.yml) runs daily at 04:00 UTC, commits any change back to `main`, which triggers a Netlify rebuild. No secrets needed — both APIs are public.

To change the show ID or RSS URL, set `STORYS_SHOW_ID` / `STORYS_RSS_URL` env vars (locally or in the workflow).

## Bilingual

- Toggle: `.lang-btn` (header) and `.im-lang__btn` (map page) both write `localStorage.storys.lang` and apply translations in-place.
- All translated strings live in `src/data/i18n.ts`. Map-specific strings live inline in `src/pages/map.astro` (`LOCAL_I18N` block) — preserved from the original v3 build to keep that page self-contained.
- Default language is **zh** on first visit.

## Featured pages

### `/brands/[id]` — dedicated brand page
Every brand in `brands.ts` automatically gets a permanent URL: `storys.fm/brands/zhenfan`, `storys.fm/brands/vacanza`, etc. Pages include hero, locations (retail only), all episodes, related brands by category, and a CTA to apply. These are great to share with sponsors — they get a permanent SEO link from your domain to theirs.

Generated automatically by `src/pages/brands/[id].astro` via Astro's `getStaticPaths()` — no manual work to add new pages, just add a brand to `brands.ts`.

### `/visit` — Visit Planner
Pick 2–6 retail brands. The page builds a numbered walking route on a dark Leaflet map, then offers one-click "Open in Google Maps" with all stops as waypoints. The route is encoded in the URL hash (e.g. `/visit#zhenfan,vacanza,nubra`) so anyone can share a curated route just by sharing the URL — no server, no accounts.

Great for Instagram captions and audience engagement.
