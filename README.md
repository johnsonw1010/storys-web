# Storys Web

Bilingual (繁中 / EN) website for **Storys Podcast** (formerly 創業之聲) — a Taiwanese
podcast about brand founders, with an interactive map of the featured brands' physical stores.

> **Current status, roadmap, and key decisions live in [`PLAN.md`](PLAN.md).**
> This README is the evergreen "what it is / how to run it" reference. For where the
> project is *right now*, read `PLAN.md`.

- **Stack:** [Astro](https://astro.build) (static-site generator), vanilla CSS, Leaflet for the map. No React. No database.
- **Hosting:** Cloudflare Workers (`@astrojs/cloudflare`, `output: "hybrid"`).
- **Content (today):** hardcoded in `src/data/` — migrating to a Google "Master Sheet" (see `PLAN.md` → Phase 1).
- **Episodes:** synced from the podcast feed via a GitHub Action.

---

## Quick start

```bash
npm install
npm run dev            # local dev with HMR → http://localhost:4321
npm run build          # produces dist/
npm run preview        # build + run the real Worker locally → http://localhost:8787
npm run sync-episodes  # refresh src/data/episodes.json from the feed
```

Requires **Node 22+** and **npm 10+**.

---

## Deploying (Cloudflare Workers)

Deploy is **manual** — a `git push` does **not** ship the site.

```bash
npm run build && npx wrangler@4 deploy
# or: npm run deploy
```

- `wrangler` is OAuth-logged-in locally. Config lives in [`wrangler.jsonc`](wrangler.jsonc).
- Live URL: https://storys-web.johnsonwang1010.workers.dev (custom domain `storys.fm` not attached yet).
- Auto-deploy on push (a GitHub Action running `wrangler deploy`, or Workers Builds) is planned — see `PLAN.md` → Phase 2.
- Large pushes over some networks need `git config http.postBuffer 524288000`.

## Editing content

> Phase 1 moves brands/locations/episodes into the Google Master Sheet (see `PLAN.md`).
> Until that pipeline is wired, the files below are canonical.

### Add or update a brand

Edit [`src/data/brands.ts`](src/data/brands.ts). Required fields per brand:

```ts
{
  id: "kkday",                 // unique slug
  nameZh: "KKday 酷遊天",
  nameEn: "KKday",
  category: "travel",          // see Category type
  type: "online",              // "retail" puts it on the map; "online" goes to the directory
  descZh: "亞洲領先的旅遊體驗預訂平台...",
  descEn: "Asia's leading travel-experiences marketplace...",
  domain: "kkday.com",         // drives logo via Google favicon API
  website: "https://www.kkday.com",
  episodes: [
    { num: 7, titleZh: "酷遊天 KKday｜創辦人 陳明明", appleId: "1000689073825" }
  ],
  // retail only — pin appears on the map for each location:
  locations: [
    {
      nameZh: "KKday 總部", nameEn: "KKday HQ",
      addressZh: "台北市信義區...", addressEn: "Xinyi District, Taipei...",
      lat: 25.038813, lng: 121.566800
    }
  ]
}
```

To find an episode's `appleId`: open the episode on Apple Podcasts, copy the URL, take the number after `?i=`.

New addresses are geocoded from the address text (lat/lng generated, not entered by hand). See `PLAN.md` → Phase 1 for the geocoding pipeline.

### Add a translation

Edit [`src/data/i18n.ts`](src/data/i18n.ts). Add the key to **both** the `zh` and `en` blocks. Reference in any `.astro` file with `data-i18n="my.key"`.

### Add an episode manually

Append to the relevant brand's `episodes` array in `brands.ts`. The episode sync keeps `episodes.json` fresh independently — but `brands.ts` remains the place to attach episodes to specific brands.

## Episode sync

The site reads episodes from `src/data/episodes.json`, regenerated by [scripts/sync-episodes.mjs](scripts/sync-episodes.mjs), which:

1. Tries the **iTunes Lookup API** first (returns Apple `trackId` per episode — preferred).
2. Falls back to the show's RSS feed if iTunes Lookup fails.
3. Writes the result, sorted newest-first.

**Run locally:** `npm run sync-episodes`.

**Run on CI:** [.github/workflows/sync-episodes.yml](.github/workflows/sync-episodes.yml) runs daily and commits any change back to `main`. **Note:** on Cloudflare that commit does **not** auto-deploy — run the deploy step above to ship it. (Phase 1 reworks this sync to read from the Master Sheet — see `PLAN.md`.)

## Bilingual

- Toggle: `.lang-btn` (header) and `.im-lang__btn` (map page) both write `localStorage.storys.lang` and apply translations in-place.
- All translated strings live in `src/data/i18n.ts`. Map-specific strings live inline in `src/pages/map.astro` (`LOCAL_I18N` block) to keep that page self-contained.
- Default language is **zh** on first visit.

## Featured pages

### `/brands/[id]` — dedicated brand page
Every brand in `brands.ts` automatically gets a permanent URL: `storys.fm/brands/zhenfang`, etc. Pages include hero, locations (retail only), all episodes, related brands by category, and a CTA to apply. Great to share with sponsors — a permanent SEO link from your domain to theirs. Generated by `src/pages/brands/[id].astro` via Astro's `getStaticPaths()` — no manual work to add new pages, just add a brand.

### `/visit` — Visit Planner
Pick 2–6 retail brands. The page builds a numbered walking route on a dark Leaflet map, then offers one-click "Open in Google Maps" with all stops as waypoints. The route is encoded in the URL hash (e.g. `/visit#zhenfang,vacanza,nubra`) so anyone can share a curated route by sharing the URL — no server, no accounts.

## Future

- **Content via Google Sheets (chosen direction):** one Master Sheet drives brands / locations / episodes (Sheets-as-CMS). See `PLAN.md`. *(Decap CMS was considered and set aside in favor of the Sheet.)*
- **Newsletter** — once you pick a provider (Resend / Beehiiv / ConvertKit), wire the footer form to their API.
- **Brand photos** — drop photos at `public/brand/photos/{brand-id}.jpg` and set `image:` on the brand. Replaces the gradient placeholder.
- **Brand logos** — drop a high-res file at `public/brand/logos/{brand-id}.png` and set `logo: true`. Bypasses the Google favicon API.
